§2Recurring habits

What shows up entry after entry

  • LLM output is untrusted input. Every AI project validates, retries, or gates the model's output rather than assuming well-formed responses.
  • Human-in-the-loop by design. Draft/approve gates, quality thresholds, verdict bands — nothing acts unsupervised.
  • Provider-swappable. Config-driven LLM choice (Gemini ↔ Ollama ↔ Claude) recurs — decoupled from any one vendor.

Engineering habits

  • TDD & test isolation — ContentPilot grew 39→98 tests; caught tests writing into real data files.
  • Explainability over black-box — log-normalized scores, significance tests, tiered evaluation, all narratable in one sentence.
  • Cost/latency awareness — cheap checks before expensive ones; background threads so UIs never block.
LOG-01

EMS 2.0 — AI Employee Management System

FastAPI · PostgreSQL · MongoDB GridFS · FAISS · Ollama (qwen2.5:7b) · sentence-transformers

Upload a resume PDF/image → a local LLM extracts structured fields → stored in Postgres, indexed in FAISS → then natural-language CRUD: "find a DevOps engineer with Kubernetes experience," "update John's email." Runs on a 6GB GPU, no data leaves the machine.

learned
  • Polyglot persistence — three stores because each is best at one job, not one store forced to do all three.
  • RAG fundamentals: retrieval gates generation so the model answers only from real records.
  • Deterministic LLM calls — temperature=0, fixed seed, tuned context window for reproducible extraction.
approach
  • Four-strategy JSON parse chain (direct → regex extract → regex cleanup → key-value fallback) + Pydantic validation, retries with a stricter prompt if the name is missing.
  • Resume scoring gate (40/100 threshold) — reject garbage before spending an LLM call.
  • Explicit threading.Thread(daemon=True), job status written to flat files the frontend polls.
alt. shelf
  • Structured-output APIs (JSON mode, function-calling, grammar-constrained decoding via Outlines/Instructor) would shrink the parse chain — unavailable for arbitrary local Ollama models, which is why the chain exists.
  • Single Postgres + pgvector + bytea instead of three stores — simpler ops, loses FAISS's raw ANN speed. A fair debate either way.
  • A real task queue (Celery/RQ/Arq) instead of raw threads — more robust at scale, heavier to run locally.
bugs handled
  • Malformed LLM JSON, markdown-fenced output, dropped fields — the core reliability problem the parse chain solves.
  • Input chaos: all-caps, emoji, unicode names, punctuation walls — documented in a stress-test suite.
  • Async timing bugs from BackgroundTasks + blocking calls → switched to explicit threads.
LOG-02

LLM Evaluation Framework

FastAPI · Celery · Redis · PostgreSQL · Streamlit · Plotly · Docker Compose

Submit a prompt/response via API → four independent evaluators run (LLM-judge, hallucination, RAG faithfulness, consistency) → results to Postgres, Slack alert on failure, live dashboard. Catches silent "model provider drift" — a vendor updates a model, quality shifts, nothing in the API contract signals it.

learned
  • Async job architecture: API returns 201 immediately, work happens on a Celery worker — the caller never waits.
  • "Is this true?" vs "did the model stay within retrieved context?" — the RAG faithfulness distinction.
  • Multi-service orchestration with Docker Compose across five services.
approach
  • Each evaluator independent with its own pass threshold — composable, individually testable.
  • Broker/worker split (Redis + Celery) so evaluation scales horizontally.
  • Dashboard polls rather than holding connections — simple, robust.
alt. shelf
  • promptfoo, Braintrust, LangSmith, Ragas, DeepEval already do this. The edge in an interview: understanding the internals, not beating them.
  • Arq or Dramatiq (async-native) vs Celery (mature, sync-oriented); RQ for simpler needs.
  • Kafka-based streaming eval if volume were high — overkill here, worth naming as the next step.
bugs handled
  • Non-determinism in scoring → averaging multiple runs to separate signal from variance.
  • Judge cost/latency → thresholds and ordering so expensive checks are gated behind cheap ones.
LOG-03

Bias & Fairness Auditor

FastAPI · Claude · VADER · DistilBERT · sentence-transformers · SciPy · fpdf2 · Streamlit

Run a prompt hundreds of times, vary only the demographic signal (name, age, religion), measure whether tone/content/quality differ. Produces a 0–100 bias score with a four-band verdict, remediation suggestions, and a PDF report structured for EU AI Act Article 13.

learned
  • Counterfactual fairness: hold everything constant, vary one signal, attribute the difference.
  • Statistical significance — one run can't separate bias from random variance; needs N runs and a real test.
  • Layered analysis: cheap signals first (word count, VADER), ML second (DistilBERT, embeddings), LLM-judge last (blind, demographics stripped).
approach
  • Four independent analysis pipelines (sentiment, semantic, structural, LLM-judge) feeding one composite score.
  • Async execution with a semaphore cap to respect rate limits.
  • Regulatory output as a first-class feature — Article 13 docs, not an afterthought.
alt. shelf
  • IBM AIF360, Microsoft Fairlearn, Google's What-If Tool — built for tabular ML, not free-text LLM output. That gap is what this fills.
  • VADER (lexicon, fast) vs a fine-tuned transformer (accurate, slow) — used both, in a two-layer design.
bugs handled
  • Statistical false positives — mitigated with significance testing, not eyeballed means.
  • Judge contamination — demographics stripped before the LLM judge ever sees a pair.
LOG-04

Prompt Regression Suite

asyncio · Pydantic v2 · GitHub Actions · Anthropic/OpenAI/Ollama · Streamlit

Each prompt gets a behavioral test suite in version-controlled YAML. Every PR touching a prompt runs its tests in CI; if quality drops below a stored baseline, the merge is blocked before the regression reaches users.

learned
  • Prompts as first-class software artifacts with version-controlled tests.
  • Reverse-index design: changed files → affected tests, so a PR touching 3 of 80 prompts runs ~12 tests, not 80.
  • Deployment-gate thinking — blocking a merge, not just reporting a number.
approach
  • Tiered assertion engine: rule checks (free) → semantic similarity (local) → LLM judge (paid, last). Fail-fast roughly halves API cost.
  • asyncio.Semaphore caps concurrent LLM calls without serializing everything.
  • Each case runs 3× and averages — one sample at temperature 0.7 is noise, not signal.
alt. shelf
  • promptfoo does much of this off the shelf — building it proves the mechanism is understood, not reinvented for its own sake.
  • Snapshot/exact-match testing — brittle for stochastic output, why semantic scoring was chosen instead.
bugs handled
  • Silent prompt regressions that green unit tests miss — the entire reason the project exists.
  • Cost blow-ups from calling the judge on everything — gated by tier ordering.
LOG-05

ContentPilot 1.0 / 2.0 — autonomous content + viral-prompt trend engine

Typer · FastAPI · Jinja2 · APScheduler · GitPython · Pydantic · Gemini / Ollama · pytest

1.0: an agent pipeline that finds trending topics, generates posts + images, pushes to a static-site git repo — dashboard, scheduler, draft/approve gate. 2.0 adds trend intelligence: pull viral prompts from Civitai + prompts.chat, score with an explainable virality metric, use an LLM to extract why each prompt works.

learned
  • Agent-pipeline design — one Orchestrator.run() reachable from CLI, dashboard button, or scheduler. One code path, three triggers.
  • Per-source failure isolation — one dead API marks a run "partial," doesn't kill it.
  • Explainable scoring — log-normalized-per-source virality, defensible in one sentence.
  • TDD at scale + test isolation — grew to 98 tests; caught tests writing into real data files.
approach
  • Draft-by-default — automated runs stage to a local drafts/ folder; nothing goes live without human approval in the dashboard.
  • Pathspec-scoped git commits (git commit -- <path>) so a run never sweeps unrelated staged work.
  • In-process APScheduler inside the dashboard — one process is the whole control plane; cron documented as the headless alternative.
alt. shelf
  • Agent frameworks (LangChain, LangGraph, CrewAI) instead of a hand-rolled orchestrator — more features, more magic, harder to reason about. Legibility was chosen deliberately.
  • Scheduling: in-process APScheduler vs system cron vs Celery-beat vs a cloud scheduler — shipped the first, documented the second.
  • Git-based publish vs a headless CMS API — git gives free version history for the cost of a commit step.
bugs handled
  • Git index sweep: index.commit() committed the whole staged index; a run could publish unrelated uncommitted work. Fixed with pathspec-scoped commits + a regression test.
  • Vendor rug-pull: gemini-2.0-flash free-tier quota silently went to zero — extraction returned zero insights with exit code 0. Diagnosed via the quota error, switched models.
  • Test pollution: orchestrator tests omitted a path arg and wrote fake runs into the real run_log.json. Isolated to tmp dirs, purged 19 fake entries.
  • Swallowed exceptions: HackerNews errors caught silently, dashboard showed a green step for a failed fetch. Let them propagate.
  • Data migration: renamed a status enum (pushed→published); old manifest.json files crashed on load until a field_validator migrated them.
  • Static-mount 404: draft images referenced a route with no mount — added a dedicated static mount.
LOG-06

Trend Engine

Python · HN/Reddit/YouTube/Wikipedia collectors · LLM dedup · SQLite · stdlib dashboard

Collects viral signals from four platforms, scores them, deduplicates + explains them with an LLM pass, publishes a ranked Top-100 report with per-platform content briefs. A zero-dependency dashboard shows pipeline stages lighting up live.

learned
  • Real-world ETL resilience — per-item batch isolation so one bad record doesn't sink a stage.
  • Working with rate limits, not against them — pacing and RSS fallbacks.
  • Cold-start problems in scoring — percentile ranking with little data.
approach
  • LLM as a dedup/enrichment pass over clustered signals, with enum-fallback validation.
  • Run-row logging + guaranteed DB-connection close even on stage crash.
  • Shared User-Agent header across collectors to stay within platform etiquette.
alt. shelf
  • Orchestrators (Airflow, Dagster, Prefect) for scheduled pipelines — heavier, real observability and retries. Hand-rolled for simplicity here.
  • Official APIs vs RSS/scraping — fell back to Reddit RSS when JSON was blocked for unauthenticated clients, a real constraint well handled.
bugs handled
  • HTTP 429 rate limits → paced fetches + RSS fallback.
  • Resource leaks → close DB connection and log a run row on crash.
  • Security: safe href schemes, idempotent DB saves (no dupes on re-run).
  • Variable shadowing, cross-cluster dedup guards, enum-fallback validation.
LOG-07

Financial Statement Parser

React · Vite · Tesseract.js (WASM) · pdf.js · Gemini 2.5 Flash · SheetJS · jsPDF

Bank statement images/PDFs → structured exports. The file never leaves the browser: OCR runs entirely in-browser via WebAssembly, only extracted text goes to Gemini for categorisation, exports land as CSV/Excel/PDF with analytics. Zero server, zero subscription, zero data liability.

learned
  • Client-side heavy compute — running OCR (Tesseract) as WASM in the browser.
  • Privacy as an architectural constraint that drives every decision, not a bolted-on feature.
  • PDF rendering pipeline: pdf.js → canvas → image → OCR.
approach
  • Send only text (capped at 8k chars) to the LLM — minimises data exposure and token cost.
  • All persistence and export happen locally in the browser.
alt. shelf
  • Server-side OCR (Google Vision, AWS Textract, Docparser) — far more accurate, but takes custody of the user's financial documents. The whole thesis is not doing that.
  • Cloud multimodal LLM on the raw image — simpler, but reintroduces the upload the architecture was designed away from.
bugs handled
  • OCR noise on low-quality scans → text cleanup before the LLM step.
  • Large-file / memory limits in-browser — 20MB cap, per-page rendering.
LOG-08

Blog — Astro static documentation engine

Astro · vanilla JS · IntersectionObserver · import.meta.glob

Drop Markdown into a folder; the build produces auto-sidebar navigation, client-side full-text search, a scroll-spy table of contents, and dark mode. The entire dist/ output is static HTML — no backend, no database.

learned
  • Build-time vs runtime separation — compute the sidebar, search index, and routes at build; defer nothing.
  • Algorithms without a library — a ~80-line weighted-scoring search engine, recursive tree-building for the sidebar.
  • IntersectionObserver with tuned rootMargin for scroll-spy.
approach
  • import.meta.glob() as a build-time filesystem API — one primitive feeds both sidebar and search.
  • Zero runtime attack surface — nothing to exploit because nothing runs server-side.
alt. shelf
  • Docusaurus / VitePress / MkDocs do this out of the box — building it proves the machinery is understood.
  • Search: the vanilla scorer vs Pagefind, FlexSearch, or Algolia — libraries scale better, this one has zero deps.
bugs handled
  • Route/path edge cases converting file paths to URLs.
  • Scroll-spy jitter — calibrated rootMargin so the right heading highlights.
LOG-09

Outflo & Portfolio — production frontends

Next.js 14 (App Router, SSG) · TypeScript · Tailwind · gray-matter · remark · Vercel

Outflo is a Next.js prompt/workflow platform — SSG, SEO metadata, dynamic slug routing, markdown rendering, dark mode, local-storage bookmarks — and the live target ContentPilot publishes into. The portfolio is a lightweight static site on Vercel.

learned
  • Static generation and SEO on the modern Next.js App Router.
  • Markdown-as-CMS — frontmatter parsing + remark rendering, no database.
  • Clean Vercel deployment, CI-driven publishing (ContentPilot pushes → Vercel builds).
alt. shelf
  • SSR / ISR instead of pure SSG if content changed per-request — unnecessary for a content site.
  • A real CMS (Sanity, Contentful) vs markdown files — heavier, editor-friendly.

§3Bug taxonomy — the classes actually handled

The section that turns "I fixed a bug" into "I recognise this category of failure." Each drawn from real commits above.

class 01

LLM output is malformed / untrusted

Malformed JSON, markdown code fences, dropped fields, hallucinated content.

Seen in: EMS's 4-strategy parse chain; ContentPilot's draft/approve gate; Bias Auditor's blind judge. General fix: validate with Pydantic, retry with a stricter prompt, gate behind a human, or constrain decoding.

class 02

Silent failure / swallowed errors

A caught exception hides a real failure; the system reports success while doing nothing.

Seen in: HackerNews exceptions swallowed → green dashboard step for a failed fetch; Gemini quota=0 returned zero insights at exit code 0. General fix: let errors propagate to a handler that records them; never conflate "ran" with "succeeded."

class 03

Over-broad side effects

An operation touches more than it should.

Seen in: git index.commit() committed the whole staged index instead of one file. General fix: scope the operation explicitly (pathspec-scoped commit) + a regression test proving the blast radius is contained.

class 04

Test / environment contamination

Tests mutate real state; the environment isn't isolated.

Seen in: orchestrator tests wrote into the real run_log.json. General fix: inject paths, use tmp_path fixtures, never let a test default to a production file.

class 05

External-dependency instability

Rate limits, auth changes, vendor rug-pulls, blocked endpoints.

Seen in: Reddit 429 → RSS + pacing; Reddit JSON blocked for anonymous clients; Gemini free tier pulled. General fix: back-off/pacing, fallbacks, provider-swap via config, graceful degradation.

class 06

Data / schema migration

Old persisted data no longer matches new code.

Seen in: renamed status enum crashed old manifest.json files. General fix: a validator/migration that upgrades legacy records on read.

class 07

Resource lifecycle & concurrency

Leaked connections, blocking the event loop, thread timing.

Seen in: DB connection left open on stage crash; BackgroundTasks + blocking calls → explicit threads; sync work must not block FastAPI's loop → executor offload. General fix: ensure cleanup on all paths, keep blocking work off the event loop.

class 08

Non-determinism in evaluation

One stochastic sample treated as a reliable signal.

Seen in: prompt tests and bias runs average N samples; statistical significance testing. General fix: multiple runs + aggregation/significance, not a single reading.

class 09

Web plumbing

Static mounts, safe URL schemes, idempotency.

Seen in: draft-image 404 from a missing mount; safe href schemes; idempotent DB saves. General fix: mind the boundary between routes and static assets, make re-runs idempotent.

Interview move The sharpest question an interviewer asks is "why did you build it instead of using X?" The honest answer across every entry: for a learning project, building it is the point — the internals, the failure modes, and the cost trade-offs are now understood firsthand. In production the off-the-shelf tool gets used, and its internals can be described precisely because they've already been written once. That answer signals maturity, not naïveté.

§5Honest gaps — what to learn next

Thin spots across the portfolio

  • Scale & load. Everything runs single-user/local — no load testing, horizontal scaling, or p99-latency story yet.
  • Observability. Logging to JSON/DB rows; no metrics or tracing (Prometheus, OpenTelemetry).
  • Auth & multi-tenancy. Dashboards are localhost, no real authn/authz.
  • Cloud/CD. Vercel deploys exist; no containers-in-prod, IaC, or k8s story.

Highest-leverage next steps

  • Add real observability to one project — the most-asked "what's missing" in AI-infra interviews.
  • Load-test the LLM Eval Framework, get a real throughput/latency number to quote.
  • Containerise + deploy one service to a cloud with IaC, end to end.
  • Take one project from POC to genuinely production-hardened, rather than starting another.
