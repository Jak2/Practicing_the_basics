Verdict

✗ Not RAG ✗ Not Multi-Agent ✓ LLM-Augmented Data Pipeline (agentic ETL)

Deterministic collection and scoring, with one narrow, single-shot LLM call for the one task code can't do well: clustering duplicate stories and writing natural-language explanations. No retrieval-then-generate loop, no autonomous multi-step agents.

Only one stage touches an LLM, and it's a single structured call — not a loop, not a conversation, not a decision-making agent.

Why This Is Not RAG

RAG (Retrieval-Augmented Generation) = retrieve relevant documents from a corpus → feed them as context → LLM generates an answer grounded in that retrieved context. Classic shape: user asks a question → search a knowledge base → LLM answers using what was found.

RAG requires…Our engine has…
A query to answerNo question being asked — we're producing a fresh ranked list, not answering
A retrieval step (vector/keyword search over stored docs)No retrieval — the enricher sees only *today's* scored candidates, nothing pulled from storage by similarity
Generation grounded in retrieved contextGeneration (the "why it's viral" line) is grounded in the collected item's own text, not a retrieved corpus
Where RAG really enters our product: in phase 2–3, mem0 will let the persona ask "have we covered something like this before?" by vector-searching past memories and feeding that into the write-up — that piece is RAG-shaped. But it lives in the persona/content layer, not the trend-engine core described here.

Why This Is Not a Multi-Agent Setup

Multi-agent = multiple autonomous LLM agents, each with their own reasoning loop, that plan, use tools across multiple turns, and coordinate or hand off work to each other (e.g., a planner agent dispatching researcher/writer/critic agents).

Multi-agent requires…Our engine has…
Multiple LLM-driven actorsExactly one LLM call, in one stage (the enricher)
Autonomous multi-step reasoning / tool use per agentCollectors/scorer/publisher are fixed code — zero reasoning, zero autonomy
Coordination or negotiation between agentsNothing to coordinate — strictly linear, one-directional pipeline
Common mix-up: "uses an LLM" ≠ "is agentic." An LLM call that takes fixed input and returns structured output in one shot is a function call, not an agent — no different in kind from calling a sentiment-analysis API.

Why It Is an LLM-Augmented Data Pipeline

This is standard ETL (Extract → Transform → Load) shape, with one Transform sub-step outsourced to an LLM because it needs language understanding that rules/regex can't do well:

  • Extract: collectors pull raw data from 4+ APIs
  • Transform (math): scorer computes z-score, decay, corroboration — 100% deterministic, reproducible, testable
  • Transform (language): enricher dedups near-duplicate stories and writes explanations — the one part needing semantic judgment
  • Load: publisher writes the final Top-100 to HTML/JSON and to the historical archive

Some call this pattern "agentic ETL" loosely because an LLM participates — but by the stricter definition above (autonomy, multi-step reasoning, tool use), it's more accurately an LLM-augmented pipeline: deterministic where determinism is better (reproducible rankings, cheap, testable), LLM-powered only where language understanding is genuinely required.

Dedup Funnel — From Raw Signals to Final 100

Raw items collected daily (Reddit + YouTube + HN + Wikipedia): ~800–1,500
After z-score + decay + corroboration scoring, top candidates kept: ~150
Enricher merges same-story duplicates ("GPT-6 leak" ≈ "OpenAI's new model"): ~150 → ~100–120 clusters
Final published Top 100, tagged by category/platform-fit/stage

Where It Could Become Genuinely Agentic Later

A real agentic step (phase 3 candidate): "decide which of today's Top 100 topics we actually script videos for" — considering what we've already covered (needs memory retrieval), how similar past explanations performed (needs feedback data), our upload cadence, and current niche gaps. That requires multi-step reasoning, tool use (query mem0, check the calendar, maybe re-rank), and judgment calls with no single deterministic formula — the textbook definition of a task worth an autonomous agent.
TriggerWhy it would need an agent
Memory-aware topic selectionMust retrieve past coverage (RAG via mem0) and weigh it against new candidates
Adaptive persona voiceNeeds to reason about what tone worked before, not just apply a fixed template
Multi-platform format planningDeciding Shorts vs thread vs long-form per topic requires weighing several soft constraints at once

Until then, the trend-engine core stays a clean, cheap, testable pipeline — and that's the right call: agents cost more, run slower, and are harder to debug than deterministic code. Reach for autonomy only once a step genuinely needs it.
