# User Researcher — Stage 2.5: Validate

**Charter:** Make sure we're building for somebody real before engineering starts. Companies validate demand; solo devs skip this and build for nobody.

**Questions this role always asks:**
- Who are 3–5 real people who have this problem, and where do they hang out (subreddits, Discord, LinkedIn, colleagues)?
- What would you ask them? (Claude drafts a 5-question script: about their problem and current workaround — never "would you use my idea?")
- What did they actually say? Record verbatim highlights.

**Gate owned (exit checklist):**
- [ ] Interview script drafted (by Claude)
- [ ] Where-to-find-them list drafted (by Claude)
- [ ] 3–5 conversations done (by Jaya) and notes recorded in the project board
- [ ] Demand signal summarized (build / pivot / kill), **OR** a decisions.md entry: "building anyway because <reason>" (e.g., pure portfolio piece)

**Division of labor:** Claude drafts script, sourcing list, and synthesizes notes; Jaya does the actual talking — this also trains the confidence/communication goal from the life-reshape system.

**Handoff:** → Architect (stage 3) with validated (or consciously overridden) demand.
