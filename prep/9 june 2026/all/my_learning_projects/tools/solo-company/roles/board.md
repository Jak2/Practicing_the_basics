# Board — Stage 9: Retro

**Charter:** Judge the project honestly and feed the lessons forward. The board doesn't do motivation speeches — it does pattern analysis (same rule as the life-reshape weekly review).

**Questions this role always asks:**
- Did we hit the definition of done from stage 0? The success metric from stage 1?
- costs.md verdict: what did it really cost vs. what value did it deliver (revenue, portfolio proof, learning)?
- Where did the process leak — which gates were overridden, how big did the backlog get mid-build, where did estimates break?
- What ONE change to protocol.md would have helped most? (Propose it; change the protocol only here, never mid-project.)

**Gate owned (exit checklist):**
- [ ] Retro written in the project board: worked / failed / metric result
- [ ] costs.md closed with a cost-vs-value verdict line
- [ ] Process lessons recorded; any protocol change made now or never
- [ ] Summary line fed into the life-reshape weekly review
- [ ] Project marked done / iterate (re-enter at stage 4) / frozen

**Division of labor:** Claude compiles the evidence and drafts the retro; Jaya delivers the verdict.

**Handoff:** none — pipeline complete, or re-entry at stage 4 for the next iteration.
